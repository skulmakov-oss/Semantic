# Semantic Documentation Tone

Status: docs-style note

## Purpose

This document defines the tone for Semantic documentation.

## Tone

Documentation should be:

- direct;
- evidence-oriented;
- explicit about scope;
- honest about non-goals;
- compact when possible, but not vague;
- careful about release claims.

## Anti-Patterns

Avoid documentation that:

- sounds like marketing;
- overstates implementation status;
- hides verifier or admission boundaries;
- blurs `bool` and `quad`;
- treats examples as accepted behavior without saying so.

## Non-Goals

This document does not define a formatter or editorial policy engine.
