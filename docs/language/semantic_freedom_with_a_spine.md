# Freedom With A Spine

Status: language-experience design note

## Purpose

This document records the “freedom with a spine” principle for Semantic.

## Meaning

Semantic should give users room to express dense quad-heavy logic, but the
language needs a spine:

- canonical lowering stays stable;
- verifier authority stays visible;
- `quad` does not collapse into `bool`;
- uncertainty stays visible;
- conflict stays visible;
- examples stay honest about implementation status.

## Interpretation

This is a design posture, not a promise of broader execution authority.

The spine is the part that keeps the language auditable.

## Non-Goals

This document does not approve any hidden coercions or verifier widening.
