# Semantic Onboarding Narrative

Status: language-experience design note

## Purpose

This document records the first user-facing story for Semantic.

## Narrative

The onboarding story should be:

1. write clear source;
2. let the frontend and typechecker validate it;
3. lower to canonical core semantics;
4. admit the artifact through the verifier;
5. execute only after admission;
6. keep effects behind explicit boundaries.

## Guidance

The narrative should remain visible in docs, examples, and roadmap material.

It should help users understand that Semantic is verifier-first without making
the language feel hostile.

## Non-Goals

This document does not claim new implementation behavior or relax any
admission boundary.
